# FIXPOINT — система учёта заявок ремонтной мастерской

Веб-приложение на Django для работы с заявками клиентов, назначением мастеров, статусами ремонта, услугами и складом запчастей.

## Что реализовано

- регистрация и вход клиентов, личный кабинет и история своих заявок;
- создание заявки с выбором услуги и прикреплением фото (JPG/PNG/WEBP, до 5 МБ);
- отдельный вход сотрудников в панель мастера;
- распределение заявок между сотрудниками с правами `is_staff` (назначение выполняет суперпользователь);
- мастер видит только назначенные ему заявки; суперпользователь видит все заявки;
- поиск, фильтрация, пагинация и смена статуса;
- журнал истории статусов и комментарии к заявке;
- склад запчастей, контроль минимального остатка и списание деталей в заявку с проверкой остатка;
- каталог услуг и управление услугами;
- управление сотрудниками: создание учётной записи мастера, включение/отключение доступа;
- отдельный учёт стоимости работ мастера;
- аналитика, фильтр по датам, графики статусов, динамики, популярных устройств и загрузки мастеров, экспорт Excel/PDF и печать отчёта;
- административная панель Django.

## Требования

- Python 3.12 или новее (проект собирался в окружении Python 3.14);
- Django 6.1.3;
- зависимости из `requirements.txt`.

## Запуск в Windows (PowerShell)

Откройте PowerShell в папке проекта — там, где лежит `manage.py`.

```powershell
py -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python manage.py migrate
python manage.py check
python manage.py runserver
```

Откройте `http://127.0.0.1:8000/`.

Если PowerShell запрещает активацию окружения, выполните в текущем окне:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

Затем повторите активацию.

## Администратор

Архив поставляется без пользовательской базы данных и персональных данных. После миграций создайте первого суперпользователя:

```powershell
python manage.py createsuperuser
```

Админ-панель: `http://127.0.0.1:8000/admin/`.

Суперпользователь назначает мастеров заявкам из панели мастера. Сотрудник должен иметь `is_staff=True`. Это можно настроить в админ-панели Django в разделе пользователей.

## Переменные среды

Для локальной разработки есть безопасный временный ключ по умолчанию. Перед публикацией задайте собственный `DJANGO_SECRET_KEY`, установите `DJANGO_DEBUG=False` и заполните `DJANGO_ALLOWED_HOSTS`. Пример переменных находится в `.env.example`. Django не загружает `.env` автоматически: переменные нужно задать в системе или через выбранный менеджер конфигурации.

## Данные

- `db.sqlite3` — создаётся при первом выполнении миграций;
- `media/repair_photos/` — каталог загруженных фотографий заявок;
- миграции находятся в `main/migrations/`.

После первого запуска не удаляйте базу и папку `media`, если хотите сохранить заявки и фотографии. Рекомендуется регулярно делать резервную копию обоих.

Проверки и тест-кейсы описаны в `docs/testing.md`. Дополнительные тесты охватывают стоимость работ, права управления сотрудниками и запрет списания запчастей сверх остатка. После запуска заполните `docs/test-results-template.md` фактическими результатами.

## Ограничения текущей версии

- отправка реальных писем не настроена: используется консольный backend Django;
- QR-коды, Kanban-доска и публичное развёртывание не входят в текущую реализацию;
- фото и SQLite подходят для учебной/локальной эксплуатации, но для production нужны отдельное файловое хранилище, резервное копирование, HTTPS и production-настройки сервера.


## Важные замечания перед сдачей

1. В `deliverables/Practice_Report_RepairWorkshop.docx` заполните название колледжа, ФИО, группу, руководителя и город.
2. Проведите тесты на своём компьютере: `python manage.py check` и `python manage.py test`. Запишите реальные результаты в протокол.
3. Макет интерфейса `design/prototype.html` можно открыть в браузере; это подготовленный эквивалент предварительных макетов Figma.
4. Публичная публикация требует вашего хостинга/сервера и домена. Инструкция находится в `docs/performance-and-deployment.md`; в архиве не указан фиктивный публичный адрес.
5. Проект подготовлен к Git. Для создания репозитория выполните `git init`, `git add .`, `git commit -m "Initial RepairWorkshop project"`.

## Замер времени ответа

После запуска сервера в отдельном окне выполните `python scripts/benchmark.py http://127.0.0.1:8000/ 20`. Скрипт измеряет главную страницу и страницу входа, выводит среднее время и приблизительный 95-й перцентиль. Для итогового протокола тестируйте также личный кабинет, панель мастера и отчёты после авторизации.
